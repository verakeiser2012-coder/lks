## Текущий статус деплоя
- Живой сервер: VPS **5.42.118.236** (Timeweb Cloud), Ubuntu, nginx (reverse proxy →
  Node на :3000) + pm2 (процесс называется `site`), путь на сервере `/var/www/site`.
- Сайт сейчас **за паролем** (nginx basic auth) — ещё не публичный, это временно.
- **SSH-доступ настроен**: приватный ключ уже лежит на этой машине —
  `~/.ssh/id_ed25519_djlevka_vps`, алиас в `~/.ssh/config` — `djlevka-vps`.
  Подключение: `ssh djlevka-vps`. Публичный ключ уже добавлен в
  `~/.ssh/authorized_keys` на сервере (там же ещё 3 чужих ключа от других сессий —
  не трогать). **Если новый аккаунт работает на этой же Windows-машине — ключ уже
  на месте, деплой работает сразу.** Если на другой машине — ключа не будет,
  нужно либо скопировать `id_ed25519_djlevka_vps` + `id_ed25519_djlevka_vps.pub`
  на новую машину, либо повторить процедуру добавления нового ключа на сервере
  (пароль root есть у пользователя, вводить его должен сам пользователь в
  терминале — не через ассистента, см. `gotcha`-раздел ниже).
- Деплой делается вручную: `tar czf` локально (исключая `public/uploads`, `.env`,
  `data/`, `node_modules`) → `scp` на сервер → распаковать в `/var/www/site` →
  `pm2 restart site` → проверить `pm2 logs site` и прогнать `curl` по ключевым
  страницам. Перед первой заливкой в новой сессии **сделай бэкап** текущей
  версии на сервере (`tar czf /var/www/site-backup-$(date +%Y%m%d-%H%M%S).tar.gz`) —
  один раз уже пригодилось откатиться.
- **ВАЖНО**: репозиторий общий — несколько параллельных Claude-сессий правят одни
  и те же файлы одновременно. Перед деплоем всего рабочего дерева (`git status`
  покажет много несвязанных изменений от других сессий — календарь, соцсети,
  релизы и т.п.) стоит хотя бы `node --check` по всем `.js` и smoke-test
  ключевых страниц после рестарта — один раз всплыла ссылка на несуществующую
