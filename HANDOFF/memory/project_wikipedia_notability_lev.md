Discussed 2026-08-17: user asked whether a Wikipedia page is needed to get verification checkmarks on social
platforms, and whether one is worth creating now.

**Conclusion:** Not needed for verification (Meta Verified/X Premium are paid ID-based subscriptions now; TikTok/
YouTube notability-based verification looks at independent press coverage, of which Wikipedia is just one
aggregation point, not a requirement). And not worth creating a page yet — Wikipedia's notability bar (ВП:ЗН)
needs significant coverage in independent, reliable secondary sources (real journalism), not self-published
content. Everything that currently exists about Lev (own site, socials, Spotify editorial-playlist placement) is
primary/affiliated, not independent press. Creating a page now would likely get deleted, and since the user is
Lev's parent/manager, self-created articles about a subject you manage are a Wikipedia conflict-of-interest red
flag (ВП:КИ) — raises deletion risk further.

**Threshold to revisit:** once **3-5 independent publications** about Lev exist in real media — e.g. interview/
article in a Yekaterinburg city outlet, a music blog/paпублic covering the electronic scene (re: EPs, Spotify
playlist placement), or independent press pickup of the Груша × Лев / redhead-festival angle. See
`[[project_site_lev_keiser]]` for the press/PR threads (podcast → origin story → press) that would generate this
coverage.

**Wikidata is a lower-bar alternative, discussed same session:** Wikidata's notability rule accepts an entity if
it's backed by "serious and publicly available references" — external IDs like a Spotify Artist ID or MusicBrainz
ID count, unlike Wikipedia's requirement for independent press prose. Lev likely already qualifies via his Spotify
artist profile (3 EPs) + the Spotify editorial-playlist placement. Creating a Wikidata item now is low-risk and
doesn't have Wikipedia's COI/deletion concerns.

**Wikidata does NOT itself grant social-verification checkmarks** — platforms verify via press coverage, not
structured databases. Its real payoff is feeding a **Google Knowledge Panel**. Confirmed via web search
2026-08-17: contrary to a common assumption, a **Google Business Profile is NOT the path for a musician/public-
figure Knowledge Panel** — Business Profile only drives *Local* panels (businesses: address/hours/reviews).
Personal/Branded panels for musicians come from structured music-industry databases instead: **MusicBrainz**
(most important — Google ingests discography/aliases/genres directly from it), **Spotify for Artists** and
**Apple Music for Artists** (verified artist profiles), plus Wikidata. Practical next steps for DJ Levka, in
rough priority: claim/complete a MusicBrainz entry, claim Spotify for Artists if not already done, create the
Wikidata item — Google Business Profile is not part of this path and shouldn't be pursued for this purpose.
Sources: [12AM Agency Knowledge Panel guide](https://12amagency.com/blog/google-knowledge-panel-for-musicians/),
[stackmatix guide](https://www.stackmatix.com/blog/how-to-get-google-knowledge-panel).

**Cover Art Archive researched 2026-08-17:** not a separate database — it's a MusicBrainz/Internet Archive
cooperative project storing release cover art, which Google and other services pull from. It's downstream of
MusicBrainz, not a parallel path: a release entry must exist on MusicBrainz first, then cover art is added via
that release's "Cover Art" tab → "Add Cover Art" (needs a MusicBrainz account; drag-and-drop or file select).
Uploads go through community peer review (correctness/spam/quality check), not instant publish. Practical
sequence for DJ Levka: create the artist + 3 release entries on MusicBrainz (Ikigai, Flowers, Soundstates) first,
then add each EP's cover art via Cover Art Archive once the releases exist.
Sources: [MusicBrainz — How to Add Cover Art](https://musicbrainz.org/doc/How_to_Add_Cover_Art),
[MusicBrainz — Cover Art Archive](https://musicbrainz.org/doc/Cover_Art_Archive).
