# Robokassa + Робочеки — что построено и как включить

Решение 11.09.2026: после отказа Альфа-Банка в эквайринге (ИП несовершеннолетнего, 14 лет,
эмансипация только с 16) платежи принимает Robokassa, чеки пробивают **Робочеки** —
Robokassa как платёжный агент формирует чек от своего имени. Своя касса, ФН, ОФД и
регистрация ККТ в ФНС не нужны; фискализация включена в комиссию эквайринга.
Сравнение с ЮKassa и облачными кассами — в памяти сессии; коротко: ЮKassa +1 % за чек
и НДС на комиссию, не принимает европейские карты; аренда своей кассы — от 18 тыс.
за ФН на 36 мес (на УСН короче нельзя) плюс 1,4–3,5 тыс./мес.

## Что в коде

- `src/services/payments/robokassa.js` — модуль. Без ключей в `.env` работает как
  заглушка (та же страница «Тестовая оплата», что и раньше). С ключами собирает
  ссылку на `auth.robokassa.ru/Merchant/Index.aspx` с подписью Паролем №1 и чеком
  (`Receipt`: цифровые вещи — `intellectual_activity` / `full_payment`, остальные —
  `commodity` / `full_prepayment`, ставка `none`; разница между суммой заказа и
  позициями уходит строкой «Доставка»). Проверка подписей ResultURL (Пароль №2)
  и SuccessURL (Пароль №1), запрос статуса `OpStateExt` (код 100 = оплачено; только боевой режим).
- `src/routes/checkout.js` — чекаут теперь зовёт `robokassa.createPayment`;
  добавлены `POST /checkout/robokassa/result` (отвечает `OK{InvId}`, ставит `paid`,
  выдаёт файлы, повтор безопасен), `GET /checkout/robokassa/success`,
  `GET /checkout/robokassa/fail` (возвращает вещи в корзину, страница
  `payment-failed.ejs`). Эти три пути проходят и при закрытом магазине.
- `src/utils/shopOpen.js` — магазин открывается ключами Robokassa (или ЮKassa).
- `.env.example` — переменные `ROBOKASSA_*` с комментариями.

Проверено локально 11.09: подпись формы = md5 из документации, чек сходится с суммой
копейка в копейку, ResultURL принимает верную подпись и отбивает чужую и чужую сумму,
повторное уведомление не дублирует выдачу, FailURL рисует страницу и возвращает корзину.

## Порядок включения

1. Регистрация в кабинете Robokassa на ИП Льва (ИНН 667900879141, счёт в Альфе),
   магазин `levkeiser.shop`, фискальное решение — **Робочеки**, галка «иностранные карты»
   (9,9 %; европейские/азиатские Visa/MC, кроме США, Канады, Турции и др.).
   Модерация до 3 рабочих дней; вывод активируется платежом 1 ₽ со счёта.
   Модератору — отдельный логин в `.htpasswd` (пользователь `bank` удалён 11.09).
2. Технические настройки магазина: алгоритм хэша (md5), Пароль №1, Пароль №2,
   ResultURL `https://levkeiser.shop/checkout/robokassa/result` (POST),
   SuccessURL `…/checkout/robokassa/success` (GET), FailURL `…/checkout/robokassa/fail` (GET).
3. `.env` на сервере: `ROBOKASSA_MERCHANT_LOGIN`, `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2`,
   `ROBOKASSA_SNO=usn_income` (если в кабинете не задано), `pm2 restart site`.
4. **nginx:** пока сайт под `auth_basic`, путь `/checkout/robokassa/result` надо вывести
   из-под пароля (отдельный `location ^~` без `auth_basic`, по образцу `/admin/login`),
   иначе уведомления получат 401. IP Robokassa для белого списка: 185.59.216.65, 185.59.217.65.
5. Сначала `ROBOKASSA_TEST=1` с тестовыми паролями из кабинета — прогнать заказ;
   затем `ROBOKASSA_TEST=0` с боевыми.

## Хвосты

- Второй чек при отгрузке физических вещей (54-ФЗ требует чек «полный расчёт» после
  предоплаты) — у Robokassa есть API `second-receipt`; не сделано, включить, когда
  пойдут первые отправки.
- Возвраты — API `refund-api`, из админки не вызывается.
- Валюта только рубли; для зарубежных карт конвертирует Robokassa.
