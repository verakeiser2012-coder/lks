# Printful: печать по требованию — что построено и что мешает включить

Разобрано 11.09.2026. Решение выбрать Printful (а не Printify) принято 13.08 —
приоритет качеству печати. Тут только состояние и порядок включения.

## Что мешает включить прямо сейчас — два барьера

**1. Оплата Printful.** Printful не берёт деньги с покупателя: он печатает и списывает
себестоимость с *нашего* счёта. Российскую карту он не примет. Нужна карта с
иностранным BIN — план записан в `foreign-card-and-esim.md`: Армения, лично,
с уведомлением ФНС. Пока карты нет, Printful включить нельзя вообще.

**2. Сервер сайта не достучится до Printful.** Проверено с VPS (страна IP — RU):
`api.printful.com` отвечает **403** и на v1, и на v2. С домашнего компьютера — 200,
то есть блок по хостингу/датацентру, а не по всей стране. Значит между сайтом
и Printful нужен ретранслятор за пределами РФ — самое простое это Cloudflare Worker
(бесплатно), который принимает наш запрос и повторяет его в Printful с тем же путём
и заголовками. Адрес ретранслятора прописывается в `PRINTFUL_API_BASE`.
Сделаю, когда будет аккаунт Cloudflare (или любой не-российский VPS).

## Что уже построено на сайте (11.09)

Интеграция написана так, что до появления карты и токена она **безопасна**:
ничего не отправляется, ничего не списывается, заказ не теряется.

- **Товар** получил поле «Кто изготавливает»: сами / Printful, и «Варианты Printful» —
  по строке размер и sync variant id (`M 4012345679`). Для такой вещи остаток
  не спрашивается, покупатель выбирает размер, в корзине размеры — отдельные строки.
- **Оформление**: если в корзине есть печать по требованию — адрес по полям (страна,
  город, индекс, улица), пункт выдачи недоступен, честная строка про 7–20 дней.
- **После оплаты** (`src/services/fulfillment.js`, одна точка для файлов и печати):
  `src/services/printful.js` собирает заказ и создаёт его в Printful **черновиком** —
  печать начнётся только после подтверждения в кабинете Printful. Это страховка от
  случайных списаний на старте.
- **Без токена** позиции помечаются «вручную», на `NOTIFY_EMAIL` уходит письмо со
  всем составом и адресом — оформить в кабинете Printful руками займёт минуту.
- **Админка заказа** показывает размер, статус отправки (черновик №, вручную, ошибка)
  и кнопку «Отправить в Printful ещё раз» — после ошибки или когда токен появился
  позже оплаты.

## Порядок включения, когда карта будет

1. Аккаунт Printful, привязать карту (Billing).
2. Собрать вещи в кабинете Printful (Product templates → добавить в магазин
   «levkeiser»): у каждого размера появится sync variant id — их вписать в товар на
   сайте, по строке.
3. Settings → Developers → Private token, права `orders/read`, `orders/write`;
   вписать в `.env` как `PRINTFUL_TOKEN`, при нескольких магазинах — `PRINTFUL_STORE_ID`.
4. Поднять ретранслятор (Cloudflare Worker), прописать `PRINTFUL_API_BASE`.
5. Один тестовый заказ на себя за минимальную вещь: проверить, что черновик
   появился, подтвердить его в кабинете, дождаться трека.
6. Только после этого — открыть такие товары покупателям.

## Что печатать первым

Не футболки «на всё подряд»: Printful нужен под **зарубежные заказы** — печать и
отправка из Европы/США, чтобы не возить из Екатеринбурга. Первые кандидаты из уже
готового: пара флагов «Двигаюсь медленно в быстром мире» (у Printful есть флаги),
принты обложек релизов (постеры — у них хороший постерный станок), стикеры.
Русские заказы дешевле и быстрее печатать здесь — Printful для них не нужен.
